# Data dictionary (dataset version 1, to be frozen)

Generated by `python simulator/make_dataset.py` with the time-dependent model (`hearth_transient.py`),
the sensor fault model measured in Week 3 and a fixed set of random seeds. Everything is SIMULATED.

## Splits (assigned by furnace, never by day)
| File | Furnaces | Rows | Use |
|---|---|---|---|
| train.csv | 140 | 102,200 | fit models |
| val.csv | 30 | 21,900 | choose settings (window length, loss weights) |
| test.csv | 30 | 21,900 | final scores, looked at once |
| test_ood.csv | 20 | 14,600 | stress test: carbon conductivity 38 to 45 W/m.K, above the 13 to 35 range seen in training |

Each furnace is 730 daily rows. The 200 in-range furnaces are split 70 / 15 / 15 with a fixed permutation
(split seed 2026). The out-of-range furnaces use seeds 1000 to 1019. 38 to 45 is a stress test, not a real carbon grade.

## Columns
**Identifiers:** `scenario` (furnace number), `day` (0 to 729).

**Inputs (the only columns a model may use):**
| Column | Meaning |
|---|---|
| TC1, TC2, TC3 | thermocouple readings in C at 0.2, 0.4 and 0.6 m from the carbon cold face, with 1.5 C noise. About 0.6% are blank (sensor outage). |

**Labels (what a model must estimate):**
| Column | Meaning |
|---|---|
| remaining_m | remaining wall, ceramic plus carbon (m) |
| ceramic_m, carbon_m | the two layers separately (m); not separable from three sensors when conductivities vary |
| skull_m | protective skull thickness (m) |
| iso1150_m | distance from the carbon cold face to the 1150 C isotherm (m) |

**Diagnostics (analysis only, NEVER model inputs, they would leak the answer):**
`TC1_true`, `TC2_true`, `TC3_true` (readings without noise or outages), `TC1_ss`, `TC2_ss`, `TC3_ss` (steady-state
readings), `heat_flux_Wm2`, `T_hotmetal`, `h_eff`, `T_water`, `k_c_true`, `k_cer_true`, `cup_gone`, `flow_regime`.

## Rules
1. Never tune anything on `test.csv` or `test_ood.csv`. Look at them once, at the end.
2. Split by furnace. Windows of days from one furnace must stay in one split.
3. A change to the simulator, seeds or splits makes a new dataset version with a new manifest.

## Freezing
`data/dataset_manifest.json` lists the furnace seeds of every split, the columns, the software versions and a SHA-256
checksum of each file (computed on values rounded to 4 decimals). Commit the manifest, not the CSV files, and tag the commit
`dataset-v1`. If a regenerated file has a different checksum, the data has changed.
Checksums depend on the NumPy version, so they are only comparable on the same software versions.

## Known limitations
Simulated data; several parameters are assumptions (see `parameters.csv`); sensor faults are modelled on a proxy;
the heat capacities used for the time lag are unsourced; the carbon floor of 0.70 m means end-of-life wall thicknesses are not covered.
